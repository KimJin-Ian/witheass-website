# 검색 규칙 (SEO · AEO · GEO)

`strategist.md`와 `writer.md`가 반드시 읽는다. 2026년 8월 기준 최신 리서치.
규칙이 바뀌면 "seo-guide.md를 최신 기준으로 다시 리서치해줘" 라고 요청하면 이 파일만 갱신된다.

## 개념 정리
- **SEO** — 사람이 검색창에 치는 말 그대로 맞춰 쓰는 것 ("자비출판 비용" 검색 → 그 말이 들어간 글이 위로)
- **AEO** — 챗봇(ChatGPT 등)이 질문에 답할 때 내 문장을 그대로 인용하게 만드는 것
- **GEO** — 검색 결과 맨 위 AI 요약(AI Overview)에 내 글이 재료로 들어가게 만드는 것

## 1. 네이버 블로그 규칙 (C-Rank · D.I.A)

### 알고리즘 구조
- **C-Rank**: 블로거가 특정 분야에 얼마나 전문적인지 누적 평가. 낮아도 개별 글의 D.I.A 점수가 매우 높으면 노출은 되지만, C-Rank 높은 경쟁 블로그엔 밀림 → 우리 채널을 "출판" 한 주제로 꾸준히 유지해야 함
- **D.I.A+**: 개별 문서의 정보 밀도·유용성 평가. 글자 수가 아니라 밀도가 기준
  (2026년 D.I.A 에서 D.I.A+ 로 바뀌며 "검색 의도에 얼마나 맞는가"의 비중이 커졌다)

### 제목
- 핵심 키워드를 **제목 앞부분**에 배치 (뒤로 갈수록 가중치 낮음)
- 25~40자 권장. 너무 길면 검색 결과에서 잘림

### 본문 분량
- **최소 1,500자.** 단, "1,500자의 핵심 정보 > 5,000자의 반복" — 글자 수보다 밀도
- 빈 내용으로 300자 미만 짧은 글을 하루 여러 개 발행하는 건 저품질 직행

### 이미지·시각자료
- 2026년부터 **체류시간**이 핵심 지표. 목표 체류시간 2분 이상
- 중간중간 시각자료(표·이미지) 없으면 이탈률 상승 → D.I.A 감점
- 이미지 개수·해시태그 개수에 공식 기준은 없음. 다만 텍스트만 있는 글보다 시각자료가 섞인 글이 명확히 유리

### 2026년 핵심 변화
- 단순 정보 나열형(백과사전식) 글은 **AI 브리핑(네이버 AI 요약)에 밀려 노출 기회 자체가 줄어든다**
- → 정보 나열이 아니라 "우리만의 관점 + 실제 사례"가 있어야 살아남음
- **신뢰도 중심 통합 랭킹** 도입 — 블로그·카페·웹이 한 줄로 섞여 노출된다.
  블로그끼리 경쟁하던 시절이 아니라, 같은 질문에 답하는 모든 문서와 경쟁한다
- 네이버가 권하는 글 흐름: **[핵심 요약] → [내가 겪은 시행착오] → [해결 방법]**
  요약을 맨 앞에 두는 건 AI 브리핑에 재료로 들어가기 위해서고,
  겪은 이야기를 넣는 건 AI가 못 쓰는 부분이기 때문이다 (아래 7번과 같은 이유)

### 저품질 판정 사유 (절대 걸리면 안 되는 것)
- 제목·본문에 동일 키워드 과도 반복 (어뷰징 의심)
- 검색 노출만을 목적으로 같은 문구 여러 번 반복
- 상업성 링크 과다, 부자연스러운 판매 유도
- 하루 대량 발행 (하루 1~3건이 안전, 그 이상은 어뷰징 감지 위험)

## 2. AEO 규칙 (챗봇 인용용 문장)

### 숫자를 넣으면 인용률 +34% (Authoritas 분석)
```
❌ "빠르게 출간해드립니다"
⭕ "인터뷰 2회 → 4주 내 1차 원고 → 평균 3개월 출간"
```

### 출처를 붙이면 인용률 최대 +40%
```
❌ "믿을 수 있는 출판사입니다"
⭕ "ISBN은 국립중앙도서관 서지정보유통지원시스템에 저자 본인 명의로 등록됩니다"
```

### ⚠️ 구글 상위 노출과 AI 인용은 이제 별개다 (2026-08-25 정정)
예전에는 "AI 답변 출처의 46%가 구글 상위 10위 안"이라 둘이 거의 같은 게임이었다.
**지금은 겹치는 비율이 20% 밑으로 떨어졌다.** 구글 1위를 해도 AI가 인용하지 않고,
구글 순위가 낮아도 AI가 인용한다.

→ 구글 순위는 구글대로(색인·내부링크·E-E-A-T), AI 인용은 AI 인용대로
   (아래 5·6번 — 답변 우선 구조와 자립 문단) 따로 준비한다.
→ 홈페이지 발행본은 구글 색인을 반드시 확인할 것 (사이트맵 자동 반영됨)

### 질문형 문장을 그대로 답으로 만들어두기
사람은 AI에게 "~해줘"가 아니라 문장으로 묻는다.
```
"자비출판이랑 기획출판이 뭐가 다른가요?" ← 이 문장 그대로를 소제목(H2/H3)이나 FAQ 질문으로 쓴다.
```

## 3. GEO 규칙 (AI 요약 노출)

### 표는 AI가 통째로 긁어간다
표·목록 형태는 AI가 그대로 인용하기 쉽다. 단, **칸을 줄여 단순하게** — 표가 복잡하면 AI도 헷갈려서 오히려 인용을 피한다. 3열이 최적.

### 반복 언급이 신뢰를 만든다
한 번 크게 터뜨린 글보다, 오랫동안 여러 채널(홈페이지·네이버·인스타)에 같은 사실이 일관되게 쌓인 쪽을 AI가 신뢰한다.

### 인물 일관성
"드림위드에스 출판사 이서진 대표"라는 표현을 모든 채널에서 동일하게 반복 사용 → AI가 이서진 대표를 하나의 '신뢰 인물'로 묶어서 기억한다.

## 4. 채널별 차이 — 절대 그대로 복붙하지 말 것

| | 홈페이지 블로그 | 네이버 블로그 |
|---|---|---|
| 분량 | 2,000~2,800자 | **2,000자 이상** (2026 기준 상향) |
| 톤 | 정보 밀도 높게, 표 중심 | 읽기 편하게, 사진 많이 |
| 목적 | AI 인용 + 구글 색인 | 네이버 검색 유입 |
| 구조 | H2/H3 + 표 + 출처 문장 | 문단 짧게 + 이미지 사이사이 |

같은 글을 그대로 두 곳에 올리면 구글이 중복 콘텐츠로 판단해 **둘 다 손해**를 본다.
반드시 문단 순서·예시·문장 구조를 다르게 재구성한다 (사실관계는 company-guide.md 기준으로 동일하게 유지).

## 5. 답변 우선 구조 (2026-08-25 추가)

AI가 인용하는 단위는 **페이지가 아니라 문단 하나**다.
검색어에 맞는 문단 하나가 뽑혀 나가고, 그 문단만으로 답이 되면 인용된다.
그래서 답을 뒤에 아껴두면 인용될 기회 자체가 없다.

이 구조로 쓴 페이지가 그렇지 않은 페이지보다 **2~4배 더 자주 인용된다.**

### 첫 문단이 곧 답이다
글을 여는 첫 문단에서 **제목이 던진 질문에 바로 답한다.** 공감이나 배경 설명을 앞세우지 않는다.

```
❌ "자비출판을 결심했지만 출판사 선택에 막혔다는 분들이 많습니다."
   → 공감 문장. 답이 없어서 인용할 것이 없다.

⭕ "자비출판 출판사는 비용·인세율·유통 범위 세 가지로 고릅니다.
   드림위드에스 출판사는 올인원 패키지 900만원에 종이책 인세 45%,
   전국 온·오프라인 서점과 전자책 4곳 유통을 2년간 보장합니다."
   → 이 문단만 떼어내도 답이 된다.
```

공감 문장을 쓰지 말라는 뜻이 아니다. **답을 먼저 주고 그 다음에 풀어쓴다.**

### 소제목마다 답을 먼저 놓는다
각 H2 아래 첫 문단은 그 소제목의 질문에 답하는 **40~75단어(한글 100~180자)** 짜리
한 덩어리로 쓴다. 이 길이가 AI가 실제로 인용해 가는 길이다.
더 짧으면 맥락이 모자라고, 더 길면 인용될 때 중간이 잘린다.

### 한 문단에 한 가지만
문단 하나에 주장을 두 개 담으면 어느 쪽도 깔끔하게 인용되지 않는다.

## 6. 자립 문단 — 문단 하나가 혼자 서야 한다 (2026-08-25 추가)

AI는 글 전체를 읽고 인용하지 않는다. **문단 하나만 떼어 가져간다.**
그 문단이 앞뒤 문맥에 기대고 있으면, 떼어놓는 순간 뜻이 무너져서 인용 후보에서 빠진다.

### 문맥에 기대는 말을 쓰지 않는다

```
❌ "앞서 말했듯 이 방식은 비용이 더 듭니다."
   → '이 방식'이 뭔지 이 문단 안에 없다. 떼어내면 무슨 말인지 알 수 없다.

⭕ "자비출판은 제작비를 저자가 부담하므로 기획출판보다 초기 비용이 더 듭니다."
   → 혼자 읽어도 뜻이 온전하다.
```

쓰지 않을 말: `앞서 말했듯` · `위에서 본 것처럼` · `이 방식은` · `그것은` · `이런 경우`
(문단 안에서 이미 이름을 밝힌 뒤라면 괜찮다)

### 이름을 밝힌다 — 문단마다 최소 한 번
`저희`라고만 쓴 문단은 떼어놓으면 **누구 이야기인지 알 수 없어** 인용되지 않는다.
각 소제목 구역에서 **처음 회사를 가리킬 때는 "드림위드에스 출판사"라고 적는다.**
같은 문단 안에서 다시 가리킬 때는 "저희"로 받아도 된다.

이건 톤을 바꾸라는 말이 아니다. `style-guide.md`의 "저희" 1인칭은 그대로 유지하되,
**구역마다 한 번은 이름이 나와야 한다**는 뜻이다.

```
⭕ "드림위드에스 출판사는 종이책 인세 45%를 지급합니다.
   저희는 출판사 마진을 최소화하는 대신 저자가 마케팅에 참여하는 구조로 이 비율을 맞춥니다."
```

## 7. 직접 겪은 이야기가 정보보다 세다 (2026-08-25 추가)

구글 **2026년 3월 코어 업데이트**가 E-E-A-T 중 첫 번째 E(Experience, 직접 경험)의
비중을 다른 모든 신호보다 크게 올렸다.
**빠짐없이 정리한 글보다, 직접 겪은 사람이 쓴 글이 위로 간다.**

정보만 잘 정리한 글은 이제 AI도 쓰고 경쟁사도 쓴다. 구분이 안 된다.
구분되는 것은 **10년·890권을 실제로 겪은 사람만 할 수 있는 말**이다.

### 글마다 최소 한 곳, 겪은 사람만 아는 이야기를 넣는다

| 넣을 자리 | 어떤 이야기 |
|---|---|
| 문제를 짚는 대목 | 상담에서 실제로 자주 받는 질문·오해 |
| 기준을 제시하는 대목 | 그 기준이 왜 생겼는지 (겪어봤기 때문에 아는 것) |
| 사례 대목 | 동의된 사례. 없으면 유형으로 (`company-guide.md` 확인) |

```
❌ "출판사를 고를 때는 계약 조건을 꼼꼼히 확인해야 합니다."
   → 누구나 쓸 수 있는 문장.

⭕ "상담에서 가장 많이 듣는 말이 '견적서를 세 장 받았는데 뭘 봐야 할지 모르겠다'입니다.
   견적서에는 총액만 적혀 있고, 정작 갈리는 건 인세율과 유통 범위인데
   그 둘은 견적서에 잘 안 적힙니다."
   → 상담을 해본 사람만 쓸 수 있는 문장.
```

### 지어내지 않는다
겪은 이야기를 넣으라는 것이지 **없는 경험을 만들라는 게 아니다.**
`company-guide.md`에 있는 사실(운영 10년, 누적 890권, 인터뷰 방식, 표절 검수 전담팀,
대표의 시작 이야기)에서 가져온다. 근거 없는 일화는 숫자 대조 검사에서 막힌다.
