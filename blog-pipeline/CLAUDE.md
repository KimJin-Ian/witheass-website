# 블로그 팀 — 팀장 지침

## 목적
드림위드에스 출판사 블로그 글을 **3일에 1건 자동 생성 → 품질 검사 → 자동 발행**한다.
홈페이지(`/blog`)에 사람 승인 없이 바로 게시된다.

## 핵심 규칙
**팀장은 직접 리서치·전략·글쓰기를 하지 않는다.** 서브에이전트만 호출·조율하고
각 단계 결과를 한 줄로 보고한다.

## 팀 구성 — 에이전트 4명 + 검사 1단계
| 단계 | 담당 | 지침 |
|---|---|---|
| ① 리서처 | 키워드 발굴 + 상위 글 구조 분석 | `agents/researcher.md` |
| ② 전략가 | 리서치 빈틈 × 회사 차별점으로 앵글 결정 | `agents/strategist.md` |
| ③ 작가 | 톤·SEO 규칙 지켜 본문 작성 (표는 HTML) | `agents/writer.md` |
| ④ 조립 | 채널별 재구성 (홈페이지 / 네이버) | `agents/assembler.md` |
| ⑤ 품질 검사 | **발행 관문** — 6종 자동 검사 | `quality-gates.md` |

이미지 제작 에이전트는 없다. **표는 이미지가 아니라 HTML `<table>` 로 만든다** —
AI 검색이 이미지 속 글자를 읽지 못하기 때문이다.

마케터(AEO·GEO) 역할은 별도 에이전트 대신 `seo-guide.md` 참고서로 두고
전략가·작가가 직접 펼쳐본다. 규칙은 매번 새로 조사할 성격이 아니기 때문이다.

## 파이프라인
```
queue.md 에서 미완료 항목 1개
   ↓
researcher   → research/[키워드].md
   ↓
strategist   → strategy/[키워드].md      (company-guide + seo-guide 참고)
   ↓
writer       → drafts/[키워드].md        (style-guide + seo-guide 참고)
   ↓
assembler    → output/[키워드]/ home.html · naver.md · meta.json
   ↓
품질 검사 6종  ─── 전부 통과 → 자동 발행 (status=published)
              └── 1종이라도 실패 → blocked + 알림, 발행 안 함
```

## 진행 보고 형식
```
[1/5] 리서처 완료 — "자비출판 비용"으로 확정, 경쟁글 11건 분석
[2/5] 전략가 완료 — 앵글: "숨은 비용 항목 비교"
[3/5] 작가 완료 — 2,340자, 표 3개
[4/5] 조립 완료 — output/자비출판-비용/ 저장
[5/5] 품질 검사 — 6종 통과 → 발행됨 /blog/self-publishing-cost
```

## ⚠️ 자동 발행 — 관문은 검사뿐이다
사람 승인 단계가 없다. `quality-gates.md` 의 6종이 유일한 방어선이므로
**검사를 우회하거나 실패를 무시하고 발행하지 않는다.**

실패한 글은 자동 재시도하지 않는다. 같은 지침으로 다시 만들면 같은 결과가 나온다.
사람이 admin에서 원인을 보고 지침을 고쳐야 다음 사이클이 나아진다.

발행 후 문제를 발견하면 admin의 **내리기** 버튼으로 `status` 를 draft 로 되돌린다.
1분 안에 사이트에서 사라지고, 글은 지워지지 않아 고쳐서 다시 올릴 수 있다.

## 지침 파일의 위치
런타임 진실은 **Supabase `pipeline_guides` 테이블**이다.
이 저장소의 `.md` 파일은 최초 시드용 원본이며, 이후 수정은 admin에서 한다.
(admin은 별도 저장소·별도 배포라 이 파일들을 디스크에서 읽을 수 없다.)
